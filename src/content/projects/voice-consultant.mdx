## Problem

Voice workflow demos can look convincing before the actual use case is clear. For this project I wanted to keep the page honest about that risk. The goal is not to present a finished assistant that sounds smooth in a demo video. The goal is to show a voice workflow in progress, keep the concept legible, and make it obvious what still needs to be proved.

## Decisions

### Keep the demo-first route live now

I kept the route live before the final walkthrough was ready because the project still belongs in the portfolio's proof order. That makes the work legible even while the demo asset is still pending. It also means the site can show the project honestly now instead of hiding it until every piece of media is polished.

### Mark the project in progress

The `in progress` label stays visible because that status is part of the proof, not an embarrassment to hide. If the workflow is not fully locked yet, the case study should say that directly. That keeps the page from overclaiming and helps the reader interpret the demo placeholder correctly.

### Reuse the same content model

I kept the same content model as the other case studies even though this project is earlier in its lifecycle. The shared structure makes the comparison cleaner: the proof here is lighter, but the page still has to answer the same questions about decisions, limitations, and implementation. That consistency helps the project feel unfinished in the right way instead of simply absent.

## What shipped

- A fixed case-study route with a demo-first intro block
- An explicit in-progress status that stays visible in the page intro
- Shared tech-note and next-project structure so the page holds together before final media arrives

## Limitations

The final demo URL and supporting screenshots are still missing, so this page cannot yet prove the workflow as directly as the other two projects. That makes this the weakest proof section in the set right now, even though the structure is in place. The page is honest about the current state, but it still depends on the recorded walkthrough to carry its weight.
